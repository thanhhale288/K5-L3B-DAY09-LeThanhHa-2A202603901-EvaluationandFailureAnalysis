Lab 9: Evaluation & Failure Analysis

Lab 8 trả lời “agent có chạy không”. Lab 9 trả lời “bản mới có tốt hơn bản cũ không, và làm sao chặn bản tệ trước khi merge”.

Mục tiêuBức tranh M0M1M2M3M4Nộp M5M6M7 Điểm

Mục tiêu

Bạn đang có một agent hoàn tiền cho công ty logistics giả lập LogiX-VN. Mỗi lần sửa agent, bạn cần một cách đo để biết nó tốt lên hay tệ đi, và một cổng CI tự động từ chối bản tệ. Lab dạy xây đúng bộ máy đó:

Biết agent sai ở đâu

Đọc trace, tìm bước sai đầu tiên, gom thành taxonomy lỗi (FM-01 … FM-09).

Tin được người chấm

Kiểm tra LLM judge bằng κ, precision, recall. Judge không đạt thì không được làm gate.

Chấm bằng code khi có tiền

Approval và số tiền chấm bằng grader trên trajectory và ledger, không tin lời agent tự khai.

Quyết định có thống kê

So hai phiên bản bằng paired bootstrap, ra CI, rồi gate exit 0 (merge) hoặc exit 1 (chặn).

Lab chạy offline: MockLLM và judge replay, không cần API key, không dùng Langfuse hay OTel. Trace cố định (14 item × 5 seed: 11, 22, 33, 44, 55), nên chạy lần nào cũng ra cùng kết quả. Không được sửa src/lab8/.

Bức tranh tổng thể

Trace của agent→M1 Taxonomy + eval set→M2 Kiểm judge→M3 Grader trajectory→M4 Bootstrap + gate→CI eval-gate

Core (M0–M4) chứng minh gate chặn được một regression rõ ràng. Advanced và Expert (M5–M7) làm khó hơn: lỗi chỉ nằm ở một slice nhỏ, lỗi chập chờn 1/5 lần, và report bị “làm đẹp” để qua gate.

M214:30Core · 12 điểm

Judge-the-judge

Mục tiêu
Quyết định tiêu chí chấm bằng LLM nào đủ tin cậy để dùng làm gate.
Cách làm
  • Cài trong stats.py: ma trận nhầm lẫn, precision, recall, Cohen’s κ (κ không xác định thì FAIL), hiệu chỉnh Rogan-Gladen.
  • Ngưỡng: κ ≥ 0.6, P ≥ 0.8, R ≥ 0.7.
  • Chạy judge trên hai file CSV (tone và helpful), rồi audit tay ≥5 chỗ judge và người bất đồng.
python -m lab9.judge --csv data/eval/judge_tone_public.csv --audit 5
Kết quả kỳ vọng
judge_tone đạt (κ≈0.757, P≈0.857, R=0.8) nên dùng được. judge_helpful không đạt nên không được làm gate. Phải giải thích vì sao, dẫn ma trận nhầm lẫn.
Nộp
docs/judge_audit.md: bảng 2 tiêu chí, ≥5 case audit (ai đúng) và hành động sửa rubric.

Paired bootstrap và CI gate

Mục tiêu
Một lệnh trả exit 0 hoặc 1 để CI quyết định merge, dựa trên khoảng tin cậy của hiệu hai phiên bản.
Cách làm
  • Cài paired_bootstrap trong stats.py: ghép cặp theo cùng item, lấy CI của hiệu PR trừ baseline. Metric nào có CI dưới sàn thì BLOCK.
  • Sinh baseline từ swarm, chạy fixed và seeded_regression qua gate.
  • Commit reports/baseline_v1.json bằng git add -f, thêm section eval vào harness_map.yaml (mẫu harness_map.eval.yaml).
python -m lab9.eval --shape swarm --out reports/baseline_v1.json
python -m lab9.eval --shape fixed
python -m lab9.gate --pr reports/eval_fixed.json --baseline reports/baseline_v1.json              # exit 0
python -m lab9.eval --shape seeded_regression
python -m lab9.gate --pr reports/eval_seeded_regression.json --baseline reports/baseline_v1.json  # exit 1
Đạt khi
pass_rate Δ −0.271, CI [−0.500, −0.057] nên BLOCK; CI lệch ≤0.01 so với tham chiếu. Job eval-gate xanh.

Nhiễu, pass@k và pass^k

Mục tiêu
Chọn ngưỡng nằm ngoài dải nhiễu, và bắt lỗi chập chờn 1/5 lần.
Cách làm

  • Đặt sàn pass_hat_5 ≥ 0.8 để chặn flaky_regression, vì pass_rate trung bình không chặn ổn định.
python -m lab9.mutation --spec config/metric_spec_v2.yaml --aa 66,77,88,99,110

Lỗi chỉ xuất hiện ở 1/3 seed không phát hiện ổn định được với 5 seed. Ghi đây là giới hạn cỡ mẫu trong eval card, đừng hạ ngưỡng để gate “bắt được”.

Gate chống gian lận eval

Mục tiêu
Gate không bị lừa bởi report bị làm đẹp: người viết PR (hoặc chính agent) có thể che lỗi thay vì sửa.
Cách làm
Cài integrity_check (số dòng, tập (item, seed), giá trị NaN, evaluator_failures) và ratchet so với --base-spec. Các trap công khai:
TrapCách gian lậnGate bắt bằng
evaluator_errors_as_nanGrader crash, giá trị thành None/NaN rồi rơi khỏi trung bìnhintegrity
dropped_failing_rowsBỏ các dòng failintegrity: số dòng
cherry_picked_seedsChỉ giữ seed đẹpintegrity: tập (item, seed)
loosened_specHạ ngưỡng, bỏ slice trong cùng PRratchet với --base-spec
python -m lab9.eval --shape slice_regression --spec config/metric_spec_v2.yaml --out reports/eval_slice_regression.json
python -m lab9.traps --pr reports/eval_slice_regression.json --baseline reports/baseline_v2.json --spec config/metric_spec_v2.yaml
# exit 0 chỉ khi gate chặn mọi trap
Đạt khi
Mỗi trap khiến gate exit 1 với lý do INTEGRITY. Chặn thêm 2 trap ẩn, baseline so với chính nó vẫn merge. Gợi ý trap ẩn có thể lọt: dòng trùng lặp, evaluator_failures trên run xanh.
